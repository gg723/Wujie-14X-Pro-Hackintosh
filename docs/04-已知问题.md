# 04 · 已知问题与判定方法

按「能不能修」分三类。**不能修的我不装作能修。**

---

## A. 不支持（本方案边界，改配置无用）

### A-1 外接显示器（HDMI / Type-C DP）

本机 GPU 走的是「**接管固件已点亮的扫描输出**」这条路，不是一个完整的显示驱动。
缺的是：

| 环节 | 缺什么 |
|---|---|
| 热插拔 | HPD 中断 → 通知 WindowServer |
| 读屏 | 通过 AUX/DDC 读外接屏 EDID |
| 链路训练 | DP 的 CR/EQ、DPCD，且依赖 **DMUB 固件** |
| 编码输出 | 第二路 DCN pipeline 的 DIG FE / UNIPHY |

实测依据：GPU 组件二进制里 `EDID` / `i2c` / `ddc` / `HPD` 关键字命中数**全为 0**，
日志写死 `one framebuffer slot (PhxFB)`。

上游 `luuumi-dev/nullarc` 的 `KNOWN_ISSUES.md` 条目 `B-11` 明确标注「进行中」，
作者正在按 Linux 内核 `amdgpu/display` 逐行移植 DCN 3.1.4。
所以正确做法是**等上游**，不是自己改 config。

短期替代：DisplayLink USB 扩展坞（绕开 DCN，走 USB 数据通路）。
代价：需要「屏幕录制」权限、无 HDCP（Netflix 类黑屏）、不适合游戏与色彩工作。

### A-2 触摸板手感（轮询，非中断）

详见 `02-ACPI补丁说明.md`。根因是 `AMDI0030`（AMD 私有 GPIO）没有 macOS 驱动，
`VoodooGPIO` 只支持 Intel GPIO 控制器。补丁能做的只是「让它动起来」，动不了「跟手」。

## B. 能改善（需要手动操作）

### B-1 显示分辨率档位少

现状：`PhxFB` 只上报固件点亮的那一档（2880×1800），EDID 里也只有一个 DTD。

**办法一（10 秒，先试）**：系统设置 → 显示器 → **按住 Option(⌥)** 再点「缩放」，
会展开成具体像素列表。

**办法二（系统自带，不用第三方 App）**：用 Display Overrides 加自定义档位。

```bash
# 1. 读出屏幕在系统里的 ID
ioreg -lw0 | grep -iE "DisplayProductID|DisplayVendorID"
# 输出通常是 DisplayProductID = 8294 (0x2066)、DisplayVendorID = 1552 (0x610)

# 2. 确认目录
sudo ls /Library/Displays/Contents/Resources/Overrides/ | head

# 3. 建目录（VendorID 用十进制）
sudo mkdir -p /Library/Displays/Contents/Resources/Overrides/DisplayVendorID-610

# 4. 写 plist（ProductID 用十进制，scale-resolutions 里是 base64 编好的分辨率）
sudo tee /Library/Displays/Contents/Resources/Overrides/DisplayVendorID-610/DisplayProductID-8294 >/dev/null <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>DisplayProductName</key>
    <string>Wujie 14X Pro Internal</string>
    <key>scale-resolutions</key>
    <array>
        <data>AAAHCAAAAOAAAAABACAAAA==</data>
    </array>
</dict>
</plist>
EOF

# 5. 注销重登（或重启）
```

> 上面的 `<data>` 是 **1920×1200** 的 base64。
> 格式是 4 个大端 uint32：`宽 / 高 / 标志位 / 保留`，
> 1440×900 为 `AAAABaAAAAOAAAAABACAAAA==`。
> 需要别的尺寸可以自己按这个规则编，或直接用下面的换算小程序。

```python
import struct, base64
def mode(w, h):                     # 生成 scale-resolutions 的 base64
    return base64.b64encode(struct.pack('>IIII', w, h, 1, 0x2000000)).decode()
for s in [(1280,800),(1440,900),(1680,1050),(1920,1200),(2048,1280),(2560,1600)]:
    print(s, mode(*s))
```

建议值（面板原生 2880×1800，16:10）：
`1280×800` / `1440×900` / `1680×1050` / `1920×1200` / `2048×1280` / `2560×1600`。
其中 **1440×900 正好是原生像素的 1/2**，文字最锐、开销最小。

### B-2 屏幕亮度延迟

`PhxBacklight` 里是有**真 PWM** 的，日志字样：

```
PhxFB: backlight: PWM at %u of %u
PhxFB: backlight: the PWM is not running (no MMIO view, or off), no brightness control
```

所以先判断走的是哪条：

```bash
log show --last 5m --predicate 'eventMessage CONTAINS "backlight"' | tail -20
```

- 出现 `PWM at ...` → 硬件调光，不延迟
- 出现 `the PWM is not running` → 退软件调光，就是你感觉到的延迟

### B-3 麦克风

先分清是「有设备没输入」还是「压根没枚举」：

```bash
system_profiler SPAudioDataType | head -60
```

- 有 `Input` 设备但电平不动 → codec 节点问题，换 `alcid` 试（21 为本机当前值）
- 没有 Input 设备 → HDA 注入路径问题，属 `SimpleHDA` 层面

### B-4 DPI 档位与字体大小

同 B-1。**注意**：与伪装机型 `MacBookPro16,1` 无关，
档位由 framebuffer 上报的模式列表决定，SMBIOS 机型名不参与这个计算。

## D. 常用诊断命令

```bash
# 显示与 framebuffer
ioreg -rc PhxAMDFB -d2 | head -40
ioreg -lw0 | grep -iE "IODisplayEDID|DisplayProductID|DisplayVendorID"

# GPU 链路
tail -30 /var/log/phxboot.log
sysctl debug.phxfb debug.phxagdc

# 触摸板是否被枚举
ioreg -lw0 | grep -iE "TPD0|PNP0C50|VoodooI2C"

# 网卡
ifconfig en0 2>/dev/null | head -5
system_profiler SPNetworkDataType | head -40

# 蓝牙
system_profiler SPBluetoothDataType | head -30
```
